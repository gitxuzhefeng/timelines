# 内容日报 P0 — 技术设计

## 架构

```
DailyReportPage (content tab)
  → api.getContentRecap(date, slice)
    → Tauri get_content_recap
      → analysis::content_recap::build_content_recap(conn, date, slice)
        → SQL 拉候选 → pick_highlight_frames() → DTO
```

## API

### `get_content_recap`

| 参数 | 类型 | 说明 |
|------|------|------|
| `date` | `string` | `YYYY-MM-DD` |
| `slice` | `"full_day" \| "evening"` | 时段 |

### 响应 `ContentRecapDto`

```ts
interface ContentRecapDto {
  date: string;
  slice: "full_day" | "evening";
  startMs: number;
  endMs: number;
  items: ContentRecapItemDto[];
  stats: {
    snapshotsInRange: number;
    ocrOkInRange: number;
    selectedCount: number;
  };
}

interface ContentRecapItemDto {
  snapshotId: string;
  sessionId: string;
  capturedAtMs: number;
  appName: string;
  windowTitle: string;
  sessionIntent: string | null;
  ocrPreview: string;
}
```

## 时段边界

- `full_day`：`local_day_bounds_ms(date)`
- `evening`：当日本地 18:00:00.000 – 23:59:59.999（与全天结束一致）

新增 `core/time_range::local_evening_bounds_ms(date)`。

## SQL（候选集）

```sql
SELECT s.id, s.session_id, s.captured_at_ms, s.perceptual_hash, s.trigger_type,
       o.ocr_text, ws.app_name, ws.window_title, ws.intent, ws.duration_ms
FROM snapshots s
INNER JOIN window_sessions ws ON ws.id = s.session_id
INNER JOIN snapshot_ocr o ON o.snapshot_id = s.id
WHERE s.captured_at_ms >= ?1 AND s.captured_at_ms <= ?2
  AND o.status = 'ok' AND o.redacted = 0
  AND length(trim(o.ocr_text)) > 0
ORDER BY s.captured_at_ms ASC
```

黑名单在 Rust 侧过滤（与 `daily_analysis` 一致）。

## 选帧 `pick_highlight_frames`

常量（`content_recap.rs`）：

| 常量 | 值 |
|------|-----|
| `MIN_SESSION_MS` | 20_000 |
| `MAX_PER_SESSION` | 2 |
| `BUCKET_MS` | 600_000 |
| `MAX_ITEMS` | 64 |
| `OCR_PREVIEW_MAX_CHARS` | 240 |

步骤：

1. 过滤黑名单、`duration_ms < MIN_SESSION_MS`
2. 按 `session_id` 分组，组内按时间扫描，跳过连续相同 `perceptual_hash`
3. 每组按 OCR 长度取 Top `MAX_PER_SESSION`
4. 合并后按 `captured_at_ms` 排序
5. 按 `captured_at_ms / BUCKET_MS` 分桶，每桶保留 OCR 最长 1 条
6. 截断 `MAX_ITEMS`
